# Development log - 2026-11

## 2026-11-01 - Quote voice transcripts and show the response label

### Result

- The Voice button stays beside Send in the conversation composer, so dictation
  can be added to a draft that already has text or attached file paths.
- A transcript is sent as a Markdown blockquote with the tag on its first line,
  separated from earlier text by a blank line; Session list and History previews
  drop the quote markers. Stored messages are not rewritten.
- The speech response may carry an optional `label`. The voice dialog shows it
  verbatim once the transcript is back and the tag becomes `[語音·<label>]`;
  without a label the tag stays `[語音]`.

### Why / context

- Mixed typed and spoken messages need a clear boundary, and a transcript that
  cannot be traced to what produced it is hard to correct.

### Evidence

- Focused UI tests cover the button layout, the quoted formats, the label in the
  dialog and tag, preview stripping and the rendered quote; they failed before
  the change.

## 2026-11-01 - Layout control in the Android app

### Result

- The Android app offers the existing session layout control (Auto and the fixed
  layouts) in its phone header; below 600 px it collapses to the menu button.
  The phone list stays the default. Once a layout is chosen, the list shows that
  many session tiles as conversation tiles on the wide layout, and the choice
  persists with the other layout settings. Opening a tile enters the same
  full-screen phone conversation, with the terminal one tap away and no side
  panel, and leaving it returns to the tiles.
- The tier helper takes a tile-grid state from Dashboard, and the root element
  now also carries `data-android-app` so the phone header can keep the control.
  Browsers and the desktop app are unchanged.

### Why / context

- After the any-width phone layout a large tablet had only a single-column list.
  Refs #219.

### Evidence

- Tests cover the unchanged phone list, a chosen layout's tiles, opening a tile,
  persistence, a browser ignoring the choice and the phone header's layout
  control at 900 px and 360 px. The repository gate result is recorded on the
  pull request.

## 2026-11-01 - Parse session notices inside the Claude paste wrapper

### Result

- A session notice that Claude records inside one whole paste wrapper
  (`<pasted_content id="...">` ... the same id on the closing tag) now parses as
  that notice, with the same kind, source, id and body as the unwrapped text, so
  a long bootstrap or handover prompt renders as a notice instead of a user
  bubble with its marker visible. A wrapper with mismatched ids, an unclosed
  wrapper, text around the wrapper or a wrapped plain message stays ordinary
  text. The parser unwraps through the existing paste helper, so no consumer
  changes.

### Why / context

- The marker must start the message, and a wrapper put the tag first. Fixes #224.

### Evidence

- Parser tests cover a wrapped and an unwrapped notice, a sample shaped like a
  Claude transcript record, and the non-notice wrapper variants. The repository
  gate result is recorded on the pull request.

## 2026-11-01 - Phone layout at any width in the Android app

### Result

- The Android app now always uses the phone layout, whatever the width: a
  tablet in landscape, even with a stylus-equipped (fine) pointer, shows the
  session list and the full-screen conversation, with the terminal one tap away
  and no side panel. Browsers and the desktop app keep the width and pointer
  tiers.
- One tier decision now drives JS and CSS: `phoneTier.ts` holds the rule and
  publishes it as `data-phone-tier` on the root element. The phone and desktop
  blocks in `styles.css` that were `(pointer: coarse)` media queries are keyed on
  that attribute (no extra specificity, through `:where`), so the Android app
  gets the phone header, filters and Settings too. Dashboard, `usePhoneLayout`,
  the reply composer and the header measurement read the same rule or attribute
  instead of repeating the query.
- Removed the `/client/viewport/...` debug probe from #208 (`recordViewportProbe`,
  its effect wiring in `useViewport` and its test); the pointer values it
  reported are confirmed. `touchPrimary` now only means a coarse pointer, since
  the Android app is always in the phone tier.

### Why / context

- A stylus-equipped device reports a fine pointer, so the width and pointer
  check left the Android app in the desktop tier at about 900 px. Refs #214.

### Evidence

- Focused tests cover the Android app at 900 px and 1400 px (conversation,
  terminal preference), rotation between 677 px and 902 px, a browser at 900 px,
  the published tier and the computed phone header. The repository gate result
  is recorded on the pull request.

## 2026-11-01 - Remove the Scope session filter

### Result

- The Session filters panel no longer offers Scope: the field, its chip, its
  counts and the `scope` filter dimension are gone. A `scope` value left in
  stored or URL state by an earlier version is ignored and never hides
  sessions. Workspace stays the only grouping facet.
- The `sessionScopes` UI extension is removed. Its role override continues as
  the separate `sessionRole` hook, which receives the records and the list
  extension data and returns a function naming each record's role for the
  Roles facet. The scope navigation field of a badge's lineage callback is gone.
- The lineage ordering helpers are renamed `LineageRecord`,
  `lineageRecordKey` and `lineageParents`; the old `ScopeRecord`,
  `scopeRecordKey` and `scopeParents` names stay as deprecated aliases for one
  release.

### Why / context

- The multi-select Workspace facet already covers grouping, and the daemon
  session record calls the field `workspace`, so one term remains.

### Evidence

- Focused tests cover the missing Scope field and chip, an ignored stored
  scope value, a host role override in the Roles facet and the exported
  aliases. The repository gate result is recorded on the pull request.

## 2026-11-01 - Stop the gate hanging silently on the UI partition self-test

### Result

- The UI partition self-test no longer re-enters a memory-scope `node` wrapper
  on PATH: its stand-in `node` leaves its own directory before calling the real
  one. The self-test and its subprocess calls have a time limit, so a regression
  fails instead of hanging.
- The validation gate runs its long steps through a stall watchdog. A step that
  prints nothing for `VALIDATION_STALL_SECONDS` (default 900, `0` disables) has
  its process group stopped, is named on stderr, and fails with status 124. A
  step that keeps printing is never stopped. A failed or killed step is named
  too.
- UI test concurrency is set by `UI_TEST_CONCURRENCY` (default 3, unchanged).

### Why / context

- With such a wrapper first on PATH the self-test looped forever with no
  output, and a hung gate looked like a slow run.

### Evidence

- A wrapper-first PATH case in the partition self-test timed out before the
  fix; new watchdog tests cover a silent step, a printing step and the step's
  own exit status.
