# Development log - 2026-11

## 2026-11-02 - Android Layout setting and themed dropdowns

### Result

- Settings on Android has one `Layout` row per device with exactly two
  options, Mobile (default) and Desktop, replacing the 1 to 6 list. Desktop
  changes only the session list screen: it shows the desktop grid with the
  header layout control (Auto and 1 to 6, any of them at any width). Opening a
  session always uses the mobile session view in both modes, and Back returns
  to the list in the chosen mode.
- A stored 1 to 6 from the earlier setting becomes Desktop with that count and
  Auto off; any other stored value becomes Mobile. The choice has a new key,
  the pane count uses the existing desktop key, the first Desktop entry uses
  Auto, and the old key is removed after the move succeeds.
- Every `<select>` in the app now goes through one wrapper: the native select in
  browsers and on macOS, the themed menu on Android, where the native popup
  ignored the app theme. The menu gained disabled options. This also
  replaces the Shell page host control that showed no icon over its text.

### Why / context

- Android could not switch panes freely or use the desktop layout on a larger
  device, and its native dropdown popups did not follow the theme.

### Evidence

- Tests cover the Settings choice, the migration (including unknown values),
  the desktop list with its layout control and an opened session in the phone
  view, the width sweep with the Android desktop list, and the wrapper on
  browser, macOS and Android; a source guard fails on any raw select.

## 2026-11-01 - Android session layout moves to Settings

### Result

- The Android app picks its session layout per device in Settings (Session
  layout): the phone list by default, or a fixed layout of one to six tiles, at
  any width. The header layout control is gone on Android, and choosing the
  phone list returns to the list. The stored layout is a new device setting; the
  earlier header choice is not read.
- The workspace header now follows the raw width tier (`data-phone-header`)
  while the tile grid follows `data-phone-tier`, so a chosen layout at phone
  width keeps the two-row phone header and the quota strip no longer draws over
  the header controls. The header's own phone rules (counts, pages, quota,
  More menu) follow the same raw width tier. In the phone header the quota strip
  takes the room left after the logo, New session, More and the counts: it
  reduces to fewer accounts, then one account without names and countdowns, and
  is hidden only when no room remains. Browsers and the desktop app are
  unchanged.

### Why / context

- On a phone with a chosen layout the grid made the whole page use the desktop
  header rules, which overlap at phone width, and there was no way back to the
  list. Refs #238.

### Evidence

- Tests cover the stored setting, the Settings choice, the tiles at 900 px,
  360 px and with a coarse pointer, no header layout control on Android, and a
  computed-box check that the header controls do not intersect at 360 px and
  412 px with and without a tile layout, and a width sweep from 320 px to
  1024 px (browser, Android and Android tile grid) that asserts no overlapping
  boxes, everything inside the header, the logo, New session and More always
  visible and equal button sizes, plus the quota strip reducing with the width
  and gone at 320 px. The repository gate result is recorded
  on the pull request.

## 2026-11-01 - Stop the gate hanging silently on the UI partition self-test

### Result

- The UI partition self-test no longer re-enters a memory-scope `node` wrapper
  on PATH: its stand-in `node` leaves its own directory before calling the real
  one. The self-test and its subprocess calls have a time limit, so a regression
  fails instead of hanging.
- The validation gate runs its long steps through a stall watchdog. A step that
  prints nothing for `VALIDATION_STALL_SECONDS` (default 900, `0` disables) has
  its process group stopped, is named on stderr, and fails with status 124. A
  step that keeps printing is never stopped. A failed or killed step is named
  too.
- UI test concurrency is set by `UI_TEST_CONCURRENCY` (default 3, unchanged).

### Why / context

- With such a wrapper first on PATH the self-test looped forever with no
  output, and a hung gate looked like a slow run.

### Evidence

- A wrapper-first PATH case in the partition self-test timed out before the
  fix; new watchdog tests cover a silent step, a printing step and the step's
  own exit status.
