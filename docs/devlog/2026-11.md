## 2026-11-05 - Retain image previews with bounded caching and request scheduling

### Result

- Conversation thumbnails and the viewer share a 48-image, 64 MiB LRU cache;
  scrolling keeps loaded blobs until eviction. Evicted thumbnails retain
  decoded dimensions. Visible residents take priority; if they fill the budget,
  new loads expose Retry instead of revoking a displayed image.
- Transient failures show Could not load with Retry and up to two automatic
  retries after 1 and 3 seconds. Not-found and deleted remain distinct.

### Why / context

- Viewport exits previously revoked loaded image URLs, while uncapped requests
  included queue delays in a 15 second timeout. A shared three-request
  visible-first FIFO queue starts that timeout only when sending; fresh
  authenticated downloads use the same cap.
- Download reauthentication and existing native copy/save behavior remain
  unchanged; the cache is only for previews and viewer reuse. Transient
  download failures show a save error without discarding shared previews.

### Evidence

- Three regression tests failed before production edits: scrolling removed the
  image, timeouts showed unavailable, and twelve requests started at once.
  Focused cache and queue tests now pass.
- Headless fixtures exercise real scrolling at 384 and 1280 px and eviction
  sizing at 360, 600, 601 and 1440 px. Paired synthetic screenshots are
  retained under pr-assets/319/.
- Review regressions first reproduced visible-eviction loading and loss of a
  thumbnail after a transient download failure. Focused coverage now holds
  visibility true through pressure, bounds all-visible admission and preserves
  preview URLs across a fresh download failure.

  stored `[語音]` and `[語音·<label>]` prompts still show correctly in

- A voice-only message looked indented for no reason.

  text before and after voice, two dictations, the no-label tag and typed
  `>` text, previews of old and new tags and the human classification; the

## 2026-11-01 - Stop the gate hanging silently on the UI partition self-test

### Result

- The UI partition self-test no longer re-enters a memory-scope `node` wrapper
  on PATH: its stand-in `node` leaves its own directory before calling the real
  one. The self-test and its subprocess calls have a time limit, so a regression
  fails instead of hanging.
- The validation gate runs its long steps through a stall watchdog. A step that
  prints nothing for `VALIDATION_STALL_SECONDS` (default 900, `0` disables) has
  its process group stopped, is named on stderr, and fails with status 124. A
  step that keeps printing is never stopped. A failed or killed step is named
  too.
- UI test concurrency is set by `UI_TEST_CONCURRENCY` (default 3, unchanged).

### Why / context

- With such a wrapper first on PATH the self-test looped forever with no
  output, and a hung gate looked like a slow run.

### Evidence

- A wrapper-first PATH case in the partition self-test timed out before the
  fix; new watchdog tests cover a silent step, a printing step and the step's
  own exit status.
